# План разработки: Telegram-бот воронки

## 📐 Подход к разработке

Идём **итеративно**:
- Каждая фаза = отдельная ветка + PR
- После каждой фазы — рабочая версия, которую можно проверить
- MVP за 5 фаз (≈ 1-2 недели работы при паре часов в день)

## 🎯 Фаза 1. Скелет проекта и `/start`

**Цель:** Бот запускается, отвечает на `/start`, пишет приветственное сообщение.

### Задачи

- [ ] **1.1.** Инициализация проекта (`pyproject.toml`, виртуальное окружение)
  - Зависимости: `aiogram`, `pydantic-settings`, `loguru`, `python-dotenv`
- [ ] **1.2.** Структура папок (`src/bot/`, `src/db/`, `src/config.py`, `tests/`)
- [ ] **1.3.** Конфиг через `pydantic-settings`:
  - `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `DB_URL`, `LOG_LEVEL`
- [ ] **1.4.** Точка входа `src/main.py`:
  - Создание бота
  - Регистрация роутеров
  - Запуск через `Dispatcher`
- [ ] **1.5.** Хэндлер `/start` в `src/bot/handlers/start.py`
- [ ] **1.6.** Тексты в `src/bot/messages.py` (отдельный модуль для редактирования)
- [ ] **1.7.** Логирование через `loguru` (вывод в stdout + файл)
- [ ] **1.8.** `.env.example`, `README.md` с инструкциями
- [ ] **1.9.** `Dockerfile` + `docker-compose.yml`
- [ ] **1.10.** Локальный тест: запуск, отправка `/start` боту

**Результат:** работающий бот, который умеет приветствовать.

## 🎯 Фаза 2. База данных и приём ключевых слов

**Цель:** Бот распознаёт `СОН` и `ТИХО`, сохраняет пользователей в БД, отправляет лид-магнит.

### Задачи

- [ ] **2.1.** Подключение SQLAlchemy 2.0 (async) + Alembic
- [ ] **2.2.** Модель `User` (`src/db/models.py`)
- [ ] **2.3.** Модель `FunnelState`
- [ ] **2.4.** Первая Alembic-миграция (`alembic init`, `alembic revision --autogenerate`, `alembic upgrade head`)
- [ ] **2.5.** Репозиторий `UserRepository` (создание/обновление/получение)
- [ ] **2.6.** Middleware для прокидывания `db_session` в хэндлеры
- [ ] **2.7.** Хэндлер ключевых слов в `src/bot/handlers/keywords.py`:
  - На `СОН` (case-insensitive): отправка PDF + текст из `messages.py`
  - На `ТИХО`: отправка описания продукта + inline-кнопка "Купить"
- [ ] **2.8.** Положить `lead_magnet.pdf` в `content/`
- [ ] **2.9.** Тест: написать боту `СОН`, получить PDF; написать `ТИХО`, получить описание

**Результат:** воронка работает в ручном режиме (без прогрева и оплаты).

## 🎯 Фаза 3. Прогрев и планировщик

**Цель:** После `СОН` пользователь автоматически получает 5 сообщений по расписанию.

### Задачи

- [ ] **3.1.** Подключение APScheduler (jobstore = SQLAlchemy для persistence)
- [ ] **3.2.** Тексты прогрева в `src/bot/messages.py` (5 сообщений из `docs/06-posts-stories.md`)
- [ ] **3.3.** Job-функция `send_warmup_step(user_id, step)` в `src/scheduler/jobs.py`
- [ ] **3.4.** В хэндлере `СОН`: запланировать 5 jobs (через 1 час, 1 день, 2 дня, 3 дня, 4 дня)
- [ ] **3.5.** Хэндлер команды "стоп" / "отписаться" — отменяет все jobs пользователя
- [ ] **3.6.** В случае покупки — отменять прогрев
- [ ] **3.7.** Тест: написать `СОН`, получить через 1 час первое сообщение, потом каждый день следующее

**Результат:** автоматический прогрев работает.

## 🎯 Фаза 4. Платежи (Tinkoff или ЮKassa)

**Цель:** Пользователь нажимает "Купить", оплачивает, автоматически получает доступ.

> ⚠️ Перед фазой нужно **выбрать одного провайдера** (Tinkoff Касса или ЮKassa) и зарегистрироваться.

### Задачи (вариант с ЮKassa)

- [ ] **4.1.** Регистрация в ЮKassa, получение `SHOP_ID` и `SECRET_KEY`
- [ ] **4.2.** Установка SDK `yookassa`
- [ ] **4.3.** Модель `Payment` в БД + миграция
- [ ] **4.4.** Клиент `src/payments/yookassa.py`:
  - Метод `create_payment(user_id, amount)` → возвращает URL оплаты
- [ ] **4.5.** В хэндлере кнопки "Купить" (после `ТИХО`):
  - Создать запись Payment
  - Получить URL оплаты
  - Отправить пользователю кнопку с URL
- [ ] **4.6.** FastAPI-приложение для webhook (`src/payments/webhook.py`):
  - Endpoint `POST /webhooks/yookassa`
  - Проверка подписи
  - При успешной оплате — обновление статуса в БД
  - Создание ссылки-приглашения в Telegram-канал программы
  - Отправка пользователю ссылки + старт программы
- [ ] **4.7.** Запуск FastAPI параллельно с aiogram (через `asyncio.gather`)
- [ ] **4.8.** Настройка домена/Cloudflare Tunnel для webhook (HTTPS)
- [ ] **4.9.** Тест с тестовой оплатой ЮKassa
- [ ] **4.10.** Уведомление администратора (тебя) о новой продаже

### Альтернативные задачи (вариант с Tinkoff Касса)
- [ ] Использовать вместо `yookassa` библиотеку или прямые HTTP-запросы к Tinkoff API
- [ ] Остальное идентично

**Результат:** реальная оплата работает end-to-end.

## 🎯 Фаза 5. Доставка программы (7 дней уроков)

**Цель:** Купивший каждый день в 09:00 получает урок.

### Задачи

- [ ] **5.1.** Создать тексты 7 уроков в `content/lessons/day1.md` ... `day7.md` (или попросить пользователя написать)
- [ ] **5.2.** Записать 3 аудиопрактики (этот шаг не входит в код, но нужен для контента)
- [ ] **5.3.** Модель `ProgramProgress` + миграция
- [ ] **5.4.** Job `send_daily_lesson()` — каждый день в 09:00:
  - Найти всех с `status = 'paid'` и `current_day < 7`
  - Отправить им урок текущего дня
  - Инкрементировать `current_day`
- [ ] **5.5.** На 7-й день — отправить опрос-отзыв (Telegram poll или просьба написать текстом)
- [ ] **5.6.** Сохранение отзывов в БД
- [ ] **5.7.** Команда `/my_progress` для пользователя — показывает текущий день
- [ ] **5.8.** Тест: купить, получать уроки 7 дней (можно ускоренно для теста — раз в минуту)

**Результат:** программа доставляется автоматически.

## 🚦 Готовность к старту

Сейчас можно стартовать **Фазу 1** в любой момент. Достаточно:
- Создать бота через @BotFather и получить токен
- Создать VPS (или временно запускать на своём ПК для теста)

После того как пользователь даст команду «начинаем фазу 1» — создаётся отдельная ветка `feature/bot-phase-1-skeleton` и код пушится туда.
